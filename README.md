# Developer Landing — Владислав Андрест

Лендинг-презентация frontend-разработчика с рабочей контактной формой, backend/API-частью и AI helper.

Проект сделан как тестовое задание: важно было показать не только красивую верстку, но и полный цикл работы приложения:

**frontend → API → обработка ошибок → результат**

## Демо

- Deploy: `сюда вставить ссылку на Vercel`
- GitHub: `сюда вставить ссылку на репозиторий`

## О проекте

Сайт представляет разработчика через несколько смысловых блоков:

- информация о себе и стеке;
- подход к работе над задачами;
- карточки проектов;
- подробное описание проектов в модальных окнах;
- AI helper для генерации краткого описания;
- контактная форма с отправкой писем;
- обработка loading / success / error состояний.

В проекте представлены 4 кейса:

1. **Fin-Panel** — интерфейс мониторинга операций и антифрод-аналитики.
2. **Friendly** — TMA для студенческих знакомств.
3. **Citizen** — гражданский портал для анализа больших данных.
4. **LiDAR Archaeology** — дипломный проект для обработки LiDAR-данных и поиска археологических кандидатов.

## Как запустить проект локально

Склонировать репозиторий:

```bash
git clone <repository-url>
cd developer-landing
```

Установить зависимости:

```bash
npm install
```

Создать файл `.env.local` в корне проекта:

```env
CONTACT_OWNER_EMAIL=your-email@example.com
MAIL_FROM="Developer Landing <onboarding@resend.dev>"
CONTACT_MOCK_EMAIL=true

AI_MOCK_MODE=true
OPENAI_MODEL=gpt-4o-mini
```

Запустить проект:

```bash
npm run dev
```

Открыть в браузере:

```txt
http://localhost:3000
```

## Переменные окружения

Для локальной разработки можно использовать mock-режимы:

```env
CONTACT_MOCK_EMAIL=true
AI_MOCK_MODE=true
```

В этом режиме форма и AI helper не требуют внешних API-ключей.

Для production-режима нужны реальные ключи:

```env
CONTACT_OWNER_EMAIL=your-email@example.com
MAIL_FROM="Developer Landing <onboarding@resend.dev>"
CONTACT_MOCK_EMAIL=false
RESEND_API_KEY=your_resend_api_key

AI_MOCK_MODE=false
OPENAI_API_KEY=your_openai_api_key
OPENAI_MODEL=gpt-4o-mini
```

## Как реализована форма

Форма обратной связи находится в секции контактов и содержит поля:

- имя;
- телефон;
- email;
- комментарий.

Форма реализует несколько состояний:

- обычное состояние;
- состояние загрузки при отправке;
- успешная отправка;
- ошибка отправки;
- ошибки валидации.

После отправки данные уходят на API route:

```txt
POST /api/contact
```

На сервере выполняется:

1. Проверка метода запроса.
2. Получение данных формы.
3. Валидация обязательных полей.
4. Проверка корректности email.
5. Проверка длины комментария.
6. Отправка письма владельцу сайта.
7. Отправка копии письма пользователю.
8. Возврат результата на frontend.

Если письмо отправлено успешно, пользователь видит success-сообщение.

Если произошла ошибка, пользователь видит понятное error-состояние, а кнопка снова становится доступной.

Для отправки писем используется Resend. В локальном mock-режиме данные формы выводятся в консоль сервера, чтобы можно было проверить сценарий без реальной отправки email.

## Как реализован AI helper

AI helper находится в отдельной секции сайта и работает через API route:

```txt
POST /api/ai-summary
```

Пользователь может выбрать тон генерации:

- краткий;
- дружелюбный;
- технический.

После этого frontend отправляет запрос на сервер. Сервер либо обращается к OpenAI API, либо возвращает fallback-ответ, если включен mock-режим.

В интерфейсе реализованы:

- выбор тона;
- loading-состояние;
- success-состояние;
- error-состояние;
- fallback при недоступном AI API.

AI helper добавлен как небольшая демонстрация интеграции с AI API и серверной обработки запроса.

## Деплой

Проект можно деплоить на Vercel, так как он использует Next.js и serverless API routes.

Для деплоя нужно:

1. Запушить проект на GitHub.
2. Импортировать репозиторий в Vercel.
3. Добавить переменные окружения в Vercel Project Settings.
4. Выполнить production deploy.
5. Проверить работу формы и AI helper на опубликованной ссылке.

## Почему выбран такой подход

Next.js выбран потому, что позволяет в одном проекте показать и frontend, и минимальную backend/API-часть. Это удобно для тестового задания, где нужно продемонстрировать полный цикл работы приложения.

SCSS Modules выбраны для изоляции стилей компонентов и аккуратной структуры проекта.

API routes используются для обработки формы и AI helper, чтобы не выносить backend в отдельный сервис и сохранить проект компактным.
